## Track G1: Fix Role Switching Not Updating Dashboard UI

### Task G1: Force content area rebuild on role change

**Files to modify:** `lib/ui/screens/school_dashboard/school_dashboard_screen.dart`
**Context files to read (if needed):** `lib/ui/screens/school_dashboard/CONTEXT.md`
**Depends on:** None
**Parallel group:** P1

**Background:**
When a user is on the school dashboard as Owner and switches to Teacher or Guardian via the role switcher at the top, the title/role badge updates but the UI/layout (nav items and content area) stays the same.

The dashboard shell (`_DashboardShellState`) has two mechanisms for reacting to entry changes:
1. `_onEntryChanged()` listener on `schoolContext.currentEntry` → recomputes `_currentItems`, recreates `TabController`, calls `setState()`
2. `ValueListenableBuilder<MembershipEntry>` in `build()` → passes new entry to `_buildContentArea()`

The content area is wrapped in a `KeyedSubtree` with a **constant** key:

```dart
// Line ~525 of school_dashboard_screen.dart
child: KeyedSubtree(
  key: const ValueKey('dashboard-content'),
  child: _buildContentArea(context, currentEntry),
),
```

This constant key preserves the widget element identity across role changes, meaning Flutter attempts to **update** the existing widget tree rather than **replace** it. While the inner `OverviewScreen` has its own `ValueListenableBuilder` to dispatch between role-specific variants, the combination of preserved element identity, intermediate `ValueListenableBuilder<Term?>` wrapper, and potential stale state in content screens causes the content to not properly update in all cases.

**Specification:**

**Step 1:** In `_DashboardShellState.build()` (around line 525), change the `KeyedSubtree` key from a constant to a role-dependent key:

```dart
// BEFORE:
child: KeyedSubtree(
  key: const ValueKey('dashboard-content'),
  child: _buildContentArea(context, currentEntry),
),

// AFTER:
child: KeyedSubtree(
  key: ValueKey('dashboard-content-${currentEntry.role}'),
  child: _buildContentArea(context, currentEntry),
),
```

This forces Flutter to tear down and rebuild the entire content subtree when the role changes (Owner → Teacher, Owner → Guardian, etc.), eliminating any stale state. When switching entries within the same role (e.g., Guardian ward A → ward B), the key stays the same, preserving scroll position and tab state — which is the desired behavior.

**Step 2:** Verify that the `_UnifiedMobileTabBar` properly rebuilds with new items. In `_buildLayout()` around line 608, the mobile tab bar receives `_currentItems` and `_tabController` — both of which are already updated in `_onEntryChanged()` before `setState()`. Verify this is working correctly by checking that `_UnifiedMobileTabBar` is a `StatelessWidget` and does not cache old items.

**Step 3:** Check the `_PillTabStrip` widget (used for teacher role mobile tabs, around line 1534). Ensure it rebuilds correctly when receiving a new `TabController` with a different `length`. If it's a `StatefulWidget`, verify that `didUpdateWidget` handles controller changes.

## Track G6: Fix Exam Paper Timetable Grid Slot Sizing

**Files to modify:** `lib/ui/screens/school_dashboard/exams/exams_grades_screen.dart`
**Context files to read (if needed):** None
**Depends on:** None
**Parallel group:** P1

**Background:**
The exam detail page shows papers in a timetable-style grid via `_PaperTimetableGrid` (around line 6714). Each row (`_PaperGridRow`, around line 6830) uses `IntrinsicHeight` + `CrossAxisAlignment.stretch` to force all cells to the same height. However, individual `_PaperSlotBox` widgets (around line 6953) use `mainAxisSize: MainAxisSize.min` and `BoxConstraints(minHeight: 52)` — they size to their content rather than expanding to fill the available cell height.

This causes:
1. A cell with "Math" (1 line) is shorter than "Business Studies & Economics" (2 lines)
2. `IntrinsicHeight` makes the ROW match the tallest cell, but the INDIVIDUAL boxes within shorter cells don't expand to fill — they sit at the top with whitespace below
3. Empty cells (`_PaperEmptyCell`) also only have `minHeight: 52` and don't grow visually to match the row

**The visual effect:** Slots appear different sizes across a row, creating misalignment.
