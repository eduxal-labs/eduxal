## Track A — Fix Mobile Modal Double-Layer & Keyboard Occlusion

### Problem Summary

On mobile, every modal launched via `showEduSheet` is **double-wrapped**:

1. **Layer 1 — `EduSheet` wrapper** (added by `showEduSheet`'s mobile path): provides `modalBg` background, top border-radius, drag handle, optional title row, and `Padding(bottom: viewInsets.bottom)` for keyboard avoidance.
2. **Layer 2 — The sheet widget itself** (e.g. `CreateSchoolSheet`): provides its own `Container` with `cs.surface` background, top border-radius, its own `_SheetHandle`, its own title/header row, and in some cases its own `viewInsets.bottom` padding on action buttons.

**Visible symptoms:**
- Two drag handles stacked vertically.
- A faint colour seam between `modalBg` and `cs.surface`.
- When the keyboard opens, the `EduSheet` padding pushes the whole sheet up, while the inner Container's constraints and/or duplicate `viewInsets.bottom` padding on buttons cause form fields to become invisible — sandwiched between two layers that both try to avoid the keyboard.

**Root cause location:** `lib/ui/widgets/edu_sheet.dart` → `showEduSheet` function, mobile branch (line ~180).

**Fix strategy:** Remove the `EduSheet` wrapper from `showEduSheet`'s mobile path. Each sheet widget is already self-contained with its own chrome (background, handle, title, constraints). On desktop, remove the `_DialogTitleRow` from the Dialog wrapper since every sheet renders its own header. After this core change, audit each sheet to ensure it properly handles `viewInsets.bottom` for keyboard avoidance.

## Track B — System Dashboard List Aesthetic Overhaul

### Problem Summary

The system dashboard's data lists (Users, Schools, Members, Roles) use a **card-based** rendering pattern:
- `_UserCard`, `_SchoolCard`, `_MemberCard`, `_RoleCard` — each is an `AnimatedContainer` with surface background, box shadow, 12px border radius, 8px bottom margin
- Hover effect: card lifts up 2px with stronger shadow
- Actions: circular icon buttons (desktop) / `MenuAnchor` with `more_vert` (mobile)
- No status-coloured accents, no press animations, no accent bars

The school dashboard members page (specifically the owners tab) uses a **rich flat-row** pattern:
- `_UserDataRow` / `_FlatRow` — separated by thin `AppTheme.tableRowDivider`
- Status-tinted background (idle/hover/press states derived from user status colour)
- Left accent bar (3–4px, animates wider on hover, coloured by status)
- Avatar with status ring border
- `ScaleTransition` press animation (scale to 0.98)
- Animated chevron that slides right on hover
- `_InlineActions` (desktop, icon buttons that fade in on row hover) / `_MobileActions` (mobile, popup menu)
- Overall much more polished, interactive, and information-dense

**Goal:** Rewrite the system dashboard list rendering in all four sections to feel similar to the school dashboard members page. The executor has creative freedom in the exact visual design — the specification below describes the **pattern and key features** to adopt, not pixel-perfect reproduction.

**Reference files:**
- `lib/ui/screens/school_dashboard/members/members_page.dart` — `_UserDataRow` (line 1898–2184), `_FlatRow` (line 2190–2423), `_FlatMemberList` (line 2744–2878), `_InlineActions` (line 2429–2447), `_MobileActions` (line 2505–2607)
- `lib/ui/theme/app_theme.dart` — `AppTheme.tableRowDivider`, status colours, `kCardRadius`
