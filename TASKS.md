**Depends on:** None
**Parallel group:** P-A

Add a top-level helper function (or extension) in `lib/core/extensions.dart` that converts a raw grade integer to a human-readable label. This eliminates the need for each screen to define its own `_gradeLabel` helper (currently duplicated in `attendance_screen.dart`, `exams_grades_screen.dart`, `announcements_screen.dart`, and `academics_screen.dart` with slight variations).

```dart
import '../models/school_config.dart';

/// Converts a raw grade integer to a human-readable label.
///
/// Uses the dual-lookup pattern: checks CBC labels first, then 8-4-4.
/// Grade numbers 41–44 are unambiguous (only exist in 8-4-4: Form 1–4).
/// Grade numbers 1–14 check CBC first (PP1, PP2, Grade 1–12).
///
/// If [config] is provided, it constrains the lookup to only the school's
/// active curricula. If null, the dual-lookup fallback is used.
///
/// **Never returns the raw integer.** Falls back to 'Level $grade' only as
/// a last resort for truly unknown values.
String gradeLabel(int grade, {SchoolConfig? config}) {
  if (config != null) {
    for (final c in config.curricula) {
      final labels = gradeLabelsFor(c.type);
      if (labels.containsKey(grade)) return labels[grade]!;
    }
  }
  // Dual-lookup fallback (no config or grade not found in config's curricula)
  return kCbcGradeLabels[grade] ??
      kEightFourFourGradeLabels[grade] ??
      'Level $grade';
}

/// Builds a "Grade · Stream" display string.
///
/// [streamName] is the resolved stream name (from CatalogDao). If null,
/// only the grade label is returned (no " · Stream X" fallback — raw stream
/// IDs must never leak to the UI).
String gradeStreamLabel(int grade, {String? streamName, SchoolConfig? config}) {
  final g = gradeLabel(grade, config: config);
  if (streamName != null && streamName.isNotEmpty) return '$g · $streamName';
  return g;
}
```

Also remove the word "Grade" as prefix from the labels returned. Per user request, the output should be just "Form 4", "Standard 3", "PP1", etc. — the existing `kCbcGradeLabels` and `kEightFourFourGradeLabels` maps already produce this format ("Form 4" not "Grade Form 4"), so no map changes are needed. The `gradeLabel` function above handles this correctly.

### Task C4: Fix "My Subjects" and "My Exams" quick stats showing 0 [x]

**Files to create/modify:** `lib/ui/screens/school_dashboard/overview/overview_screen.dart`, `lib/database/daos/memberships_dao.dart`
**Context files to read (if needed):** `lib/database/daos/memberships_dao.dart` (L232–265 for `_subjectCount`), `lib/database/daos/exams_grades_dao.dart` (L101–148 for `watchExamsForTerm`)
**Depends on:** None
**Parallel group:** P-C2

**Specification:**

**"My Subjects" showing 0:**

The `_TeacherQuickStats` widget reads `entry.subjectCount` which is pre-computed by `MembershipsDao._subjectCount()`. This method:
1. Finds the "current active term" by querying `terms` where `start <= now <= end` (in **seconds** since epoch).
2. Counts `subject_teachers` rows matching `(school, year, term, teacher)`.

The likely cause of 0 is that `_subjectCount` is computed once when the membership is loaded (home screen) and is NOT reactive — it's a `Future<int>`, not a stream. If the user opened the app before the term started or the term boundary doesn't match `now`, the count is 0 and never refreshes.

**Fix approach:**
1. In `_TeacherQuickStats`, replace the static `entry.subjectCount` with a **live `StreamBuilder`** that watches `MembersDao.watchTeacherSubjects(schoolId, userId)` filtered to the current term, then counts distinct subjects. This ensures the count is always up to date.
2. Alternatively, add a new reactive method to `MembersDao`:
```dart
Stream<int> watchTeacherSubjectCount(String schoolId, String teacherId, int year, int term)
```
That does a `selectOnly` with `count()` on `subjectTeachers` filtered by `(school, year, term, teacher)` and returns a reactive stream.

**"My Exams" showing 0:**

The `_TeacherQuickStats` widget streams `ExamsGradesDao.watchExamsForTerm(schoolId, year, term)` and then filters client-side where `e.teacher.id == userId || e.papers.any((p) => p.invigilator == userId)`.

The `teacher` field on an `Exam` is the **creator** of the exam. The `invigilator` field on a `Paper` is the teacher assigned to invigilate that specific paper. A teacher who is assigned subjects but didn't create the exam or get assigned as invigilator won't show up.

**Fix approach:**
1. Expand the filter to also match papers where the teacher **teaches the subject**. A teacher should see exams containing papers for subjects they teach to the relevant grade/stream:
```dart
final myExams = allExams.where((e) {
  // Created the exam
  if (e.teacher.id == userId) return true;
  // Is invigilator on any paper
  if (e.papers.any((p) => p.invigilator == userId)) return true;
  // Teaches the subject of any paper (needs subject_teachers data)
  if (e.papers.any((p) => teacherSubjectSet.contains(p.subject))) return true;
  return false;
}).length;
```
2. To make this work, also stream `MembersDao.watchTeacherSubjects(schoolId, userId)` to build a `Set<int>` of subject IDs the teacher teaches for the current term.
3. Add a second `StreamBuilder` wrapping the exams one to provide the teacher's subject set.

   ```dart
   debugPrint('[_RoleFormSheet._save] roundtrip: ${parsePermissions(json)}');
   ```

4. **Check for double-encoding.** A common bug is `jsonEncode(jsonEncode(data))` which produces a JSON string that's itself a string (e.g., `"\"[...]\""`). Verify that `serialisePermissions` returns a plain JSON string, not a double-encoded one.

5. **Check `didUpdateWidget` timing.** After `_save()` in `_PermissionsTabState`, the flow is:

   ```dart
   }
   ```
