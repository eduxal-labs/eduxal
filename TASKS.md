### Task A1: Privilege escalation — System user can elevate another user to Super

**Files to modify:** `lib/ui/screens/system/users/user_detail_sheet.dart`
**Context files to read:** `lib/ui/screens/system/CONTEXT.md`
**Depends on:** None
**Parallel group:** P1

**Specification:**

In `_AccountActionsCard.build()`, the "Elevate to super" action row is shown inside the `permissions.can(Resource.users, Action.update)` gate with **no** check that the viewer is Super-level. A System user with `Users.Update` can promote any System user to Super — a direct privilege escalation.

```dart
if (viewerLevel == UserLevel.super_) ...[
  _ActionRow(
    icon: Icons.arrow_upward_rounded,
    label: 'Elevate to super',
    ...
  ),
],
```

Only `UserLevel.super_` viewers should see this action. The existing `viewerLevel` variable is already available in scope (it's used for the downgrade check).

### Task B2: `SchoolPermissions` must bypass all checks for Super users ✅

**Files to modify:** `lib/models/school_permissions.dart`
**Context files to read:** `lib/models/CONTEXT.md`
**Depends on:** None
**Parallel group:** P2

**Specification:**

`SchoolPermissions.can()` delegates directly to `Permissions.can()` with no user-level awareness. Per AGENT.md §17a: "Super (2) — Bypass all checks. See everything, write anything."

Unlike `SystemPermissions` (which correctly checks `_level == UserLevel.super_` and returns `true`), `SchoolPermissions` has no level field at all. If a Super user enters a school with no roles, every `can()` check fails.

**Fix:**
1. Add a `UserLevel _level` field to `SchoolPermissions`:
```dart
class SchoolPermissions {
  final String schoolId;
  final String userId;
  final Permissions permissions;
  final UserLevel _level;

  const SchoolPermissions({
    required this.schoolId,
    required this.userId,
    required this.permissions,
    UserLevel level = UserLevel.normal,
  }) : _level = level;

  bool can(Resource resource, Action action) {
    if (_level == UserLevel.super_) return true;
    return permissions.can(resource, action);
  }

  bool canAny(Resource resource, List<Action> actions) {
    if (_level == UserLevel.super_) return true;
    return actions.any((a) => permissions.can(resource, a));
  }

  bool canAll(Resource resource, List<Action> actions) {
    if (_level == UserLevel.super_) return true;
    return actions.every((a) => permissions.can(resource, a));
  }
}
```

2. Update the constructor call site(s) — search for `SchoolPermissions(` across the codebase (likely in `school_dashboard_screen.dart` `_initializeSession()` and possibly `home_screen.dart`). Pass `level: cache.currentUser!.user.level` (or the equivalent `UserLevel` from the active account).

Import `UserLevel` from `database/tables/enums.dart` in `school_permissions.dart`.
