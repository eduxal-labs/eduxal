# ui/screens/school_dashboard/ — School Dashboard Context

> The school dashboard is the main app surface where users interact with school-scoped data.
> It is a responsive layout that adapts between desktop (sidebar navigation) and mobile (top tab navigation).

## Overview

This directory contains **1 shell screen file** and **8 subdirectories**, each representing a section of the school dashboard. All data displayed here is scoped to a specific school via `SchoolContext` and a specific academic term via `ActiveTermContext`.

## Entry Point

### `school_dashboard_screen.dart`
- **Status:** ✅ Complete
- **Widget:** `SchoolDashboardScreen` (StatefulWidget)
- **Purpose:** The responsive shell that hosts all school-scoped pages. Provides `SchoolContext` and `ActiveTermContext` to the widget tree. User menu avatar shows a badge with failed sync log count (via `LogsDao.watchFailedLogCount`). Notifications action navigates to `NotificationsPage`.
- **Layout:** Uses a single `Scaffold` with a `_LayoutMode` enum (`full`, `rail`, `mobile`) that drives which navigation chrome is shown. A `LayoutBuilder` computes `mode` inline on each constraint change and passes it directly to `_buildLayout` — no state field, no `addPostFrameCallback`, no `setState`. The `_buildLayout` method uses a **unified tree structure** for all layout modes: `Scaffold → SafeArea → Column → [mobile-only top bar, mobile-only pill tabs] → Expanded(Row → [navigationChrome, wrappedContent])`. The `content` widget always appears at the **exact same depth** in the Element tree regardless of mode — this prevents state loss when crossing the 600px breakpoint. `navigationChrome` is `_FullSidebar` for full mode, `_IconRail` for rail mode, or `SizedBox.shrink()` for mobile. `wrappedContent` uses `_wrapSidebarContent` (padded `ClipRRect` card) for full/rail and raw `Expanded(child: content)` for mobile. (Unified in Task 01; previously three separate subtrees caused element teardown at breakpoints.)
  - **Full (≥1200px):** `_FullSidebar` (232px labelled sidebar) + content area wrapped in padded `ClipRRect` card.
  - **Rail (600–1200px):** `_IconRail` (64px icon-only rail with tooltips) + same wrapped content area.
  - **Mobile (<600px):** `_TabLayoutTopBar` + `_PillTabStrip` (icon-only, elevated, with shadow indicator) + content area directly (no `TabBarView` — content driven by `_selectedIndex` for persistence).
- **Key responsibilities:**
  - Receives `SchoolMembership` + initial `MembershipEntry` from the home screen.
  - Creates `SchoolContext` with computed `SchoolPermissions`.
  - Creates `ActiveTermContext` from `TermsDao.watchTerms(schoolId)`.
  - Hosts the **Role Switcher** in the top AppBar (reads `SchoolContext.membership.entries`).
  - Hosts the **Term Selector** chip in the AppBar (reads `ActiveTermContext`).
  - Routes to content pages based on selected nav item.
  - Disposes `SchoolContext` and `ActiveTermContext` on pop.
- **Navigation items by role:**
  - **Owner:** Overview | Academics | Exams & Grades | Members | Finance | Announcements | Timetable | Roles
  - **Teacher:** Overview | My Classes | Exams & Grades | Timetable | Attendance | Announcements
  - **Staff:** Overview | Members | Finance | Attendance | Announcements
  - **Student:** Overview | Timetable | Grades | Attendance
  - **Guardian:** Overview | Attendance | Grades | Finance (read-only)
- **Dependencies:** `models/school_context.dart`, `models/school_permissions.dart`, `models/membership.dart`, `models/active_term_context.dart`, `client.dart` (DAOs, `logsDao`), `database/daos/terms_dao.dart`, `database/daos/school_scopes_dao.dart`, `ui/widgets/term_selector_chip.dart`, `ui/widgets/active_term_provider.dart`, `ui/screens/notifications/notifications_page.dart`

## Role Switcher

The role switcher widget in the AppBar reads `SchoolContext.membership.entries` and calls `SchoolContext.switchEntry(entry)` on tap. When `SchoolContext.canSwitch` is `false` (single entry), the switcher is hidden.

Switching entry:
- Does NOT recompute `SchoolPermissions` (constant for session).
- Does NOT trigger a new page — the dashboard content rebuilds in place via `ValueListenableBuilder<MembershipEntry>` on `SchoolContext.currentEntry`.
- Entry-sensitive streams (lessons filtered by teacher, grades for a guardian's ward, etc.) re-subscribe based on the new entry.

## Term Selector

The term selector chip in the AppBar reads `ActiveTermContext.currentTermLabel` and opens a picker showing `ActiveTermContext.allTerms`. Selecting a term calls `ActiveTermContext.setTerm(term)`. All term-sensitive data streams rebuild via `ValueListenableBuilder<Term?>` on `ActiveTermContext.termNotifier`.

When `ActiveTermContext.hasTerms` is `false`, the dashboard shows a blank state with a "Create First Term" CTA for owners (via `NoTermsBlankState` widget).
